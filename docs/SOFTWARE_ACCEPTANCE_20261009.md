# 软件验收复核（2026-10-09）

## 结论与范围

按已确定的 `COURSE_PROJECT_DESIGN_PLAN.md` 第 6 节 P0/P1 复核，核心业务软件链路、设备软件接口和维护工具已具备实现与自动化验收证据。本次不是仅检查页面或启动容器：核查认证与授权状态、数据持久化、设备指令、异常分支、模板工具、镜像、备份恢复和真实浏览器 API 联调，并直接修正发现的问题。

**不能将本结论表述为“除了硬件，所有可能的软件能力均已完成”。** 活体检测、直播录像、双向语音、完整 OTA 等尚未实现；原设计将这些列为范围外/另行验收能力。若“全部”包括这些能力，项目仍有软件待办。课程任务书未提供，本次也不能替代教师必做项审核。模板登记已形成运维闭环，未实现普通用户网页自助登记。

## 本次实际修复

1. TOTP 待登记生命周期集中到独立模块，数据库写锁串行化同账户登记。5 分钟窗口内复用待登记信息；超时轮换并作废旧挑战；成功绑定后历史重复待登记秘密失效，不能替换已有有效认证器。
2. 模板生成工具与识别器曾使用不同默认目录，导致生成成功却无法被识别器读取。统一配置路径、按目录隔离缓存，增加严格向量和文件验证、原子安装及安全删除。认证图像包含多张人脸时直接拒绝，不能自动选最大人脸替代明确身份。
3. 模型来源与 SHA-256 固定，生产装载前校验；下载由显式维护命令执行。设备就绪探针检查模型和有效模板，区分进程存活与识别配置完成。
4. 连续认证失败触发锁定时原来没有自动告警。现与锁定状态在同一事务中保存告警及通知任务，只在从未锁定变为锁定时入队。
5. 用户名与模板文件身份规则统一，拒绝路径字符及控制字符，仍支持中文。补齐 TOTP 绑定、访客创建/撤销的可读动作名称和新设备认证事件的设备关联。
6. 设备端回归纳入 AMD64/ARM64 CI；源码发布包包含设备测试和新运维工具，不包含模型、个人模板、密钥或数据。

- 浏览器：隔离真实 Flask API 联调通过初次绑定、设备列表、上锁命令回执、历史、访客创建/撤销及拒绝已撤销凭证。数据库为一次性夹具，设备在线状态为夹具，不伪造物理执行成功。
- 确定性页面验收：登录、命令恢复、状态、权限、访客、告警、名称、证据和空状态，以及 **35** 个响应式、**5** 个文字放大检查通过。页面测试 API 使用隔离夹具。

- 备份恢复：在停写条件下从实际数据卷创建 `deploy/backups/software-review-20261009.zip`，恢复至新的独立目录 `restore-software-review-20261009`，逐文件校验与 SQLite 完整性检查通过。未覆盖在线数据；这证明工具恢复，不替代真实灾难切换演练。

## 可重复操作

完整检查执行 `python -B deploy/verify.py`；设备构建和 13 项测试命令见部署 README。登记、替换和删除模板后在维护窗口重启设备，使只读文件与缓存一致；删除模板同时撤销后端设备授权。

`main` 仍保留旧版本。软件修复在 `develop`，最新本机入口为 http://localhost:8080/；HTTPS 为 https://localhost:8443/，浏览器须信任本地 CA。详细部署、密钥、账户恢复、通知与模板管理见 `deploy/README.md`。

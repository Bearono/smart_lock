# 安全主线任务拆解与验收清单

日期：2026-10-17。基线：develop / 743542b。本文件是待办建议，没有修改业务实现。工期为熟悉项目后的组内估计，不是承诺；必须先由成员认领。

配套：[安全流程](SECURITY_FLOW_GUIDE_20261017.md)、[硬件采购](HARDWARE_BUYING_GUIDE_20261017.md)。

## 1. 本轮完成定义

能让非原作者在固定版本上复现：可信配置 → HTTPS → SPAKE2双向确认 → 认证业务消息 → 用户MFA授权 → 一次性命令 → 可信反馈；能展示轮换、退役和故障后的拒绝行为。没有实体锁时如实停止在执行器缺失边界。

不把新增算法数量作为主指标。已有SPAKE2、GCM、防重放、原子消费和大部分安全用例继续复用，重点补生命周期、配置约束和实机证据。

## 3. 生命周期细节：建议的失效矩阵

勾选表示应实施并验证，不代表本轮已经全部做到；已存在的行为可直接补证据。

| 事件 | 新设备握手 | 旧安全会话 | 人脸认证会话 | 未用开门令牌 | 待发动作 | 执行日志/审计 |
| --- | --- | --- | --- | --- | --- | --- |
| 设备口令轮换 | 仅新秘密可用 | 撤销 | 失败 | 作废 | 撤销 | 保留，增加凭据版本 |
| 整台设备退役 | 拒绝 | 撤销 | 失败 | 作废 | 撤销 | 保留，不删除历史证据 |
| 用户某设备撤权 | 设备身份本身保留 | 通用设备会话可保留 | 该用户失效 | 该用户作废 | 该用户撤销 | 保留 |
| 账号整体撤销/改密 | 设备身份本身保留 | 通用设备会话可保留 | 用户失效 | 用户作废 | 用户撤销 | 保留，JWT版本变化 |
| 访客凭证撤销 | 不影响 | 不影响 | 不涉及普通人脸会话 | 相关访客令牌作废 | 相关访客命令撤销 | 保留 |

设备轮换/退役与访客授权的策略需明确：建议退役时停用该设备访客凭证，重新启用后要求重新签发；轮换时是否保留尚未使用的访客凭证，需要组内写定并测试，不能只检查已经发出的令牌。

撤销不等于删除日志，也不意味着能撤回已经发生的动作。

## 4. 安全实验最小矩阵

| 场景 | 实验方法 | 预期及证据 |
| --- | --- | --- |
| 正常建会话 | 两端独立秘密一致，完整start/confirm | confirmed后可业务，报告不输出会话密钥 |
| 错误身份/秘密 | 另一设备身份或错误秘密 | 不能得到可用确认会话，业务不执行 |
| 证明篡改 | 修改proofClient/proofServer或握手记录 | 验证失败，未确认会话不能提交 |
| 降级 | 伪造旧版本响应或提交旧协议 | 生产拒绝，无自动legacy回退 |
| 消息篡改 | 修改密文、GCM标签或header | 拒绝，不产生业务副作用 |
| 跨接口/方向 | 同包投另一路由或改direction | 拒绝 |
| 重放/并发 | 同信封串行和并发提交 | 至多一次进入业务，重放记录跨worker |
| 重启 | 后端重启后重放旧包；Pi重启后观察新会话 | 重放拒绝；Pi新密钥，不恢复旧nonce计数器 |
| 轮换/退役 | 保存旧秘密/会话/令牌/命令后操作 | 依据失效矩阵全部受控，无重新授权复活 |
| HTTPS身份 | 不信任CA、错SAN、过期证书 | TLS连接失败，不允许跳过检查 |
| 响应丢失 | 丢弃消费响应/回执后查询原命令 | 不重复消费或动作，显示原结果/未知 |
| 撤销竞争 | 命令取出前/后、执行开始前/后分别撤权 | 满足写定的时间边界，保留已发生事实 |

优先在隔离库做破坏性/异常测试，生产设备上只做已安排的受控演示；不提供面向正式系统的一键攻击按钮。

| H03 / 1天 | 嵌入式+后端 | 根据锁机械行为统一“脉冲释放/重新扣合”和LOCKED/UNLOCKED命令语义 | 电磁柜锁不能假装能远程机械关门；拒绝能力不支持的动作，回执语义正确 |
| H04 / 1天 | 硬件+后端 | 门磁、锁反馈、执行器状态分别建模，上报与显示；门未关超时告警 | 门开/锁闭组合能分别解释，不直接沿用目标状态 |
| H05 / 1天 | 测试+硬件 | ≥20次正常动作，加卡阻、掉电、反馈断线、重复命令、断连/重启测试 | 逐次记录，成功靠传感器；失败/未知不误报；不重复已预约动作 |

若当前预算/老师范围不支持H01–H05，将交付名称限定为摄像头终端安全与授权原型；不能用LED成功代替物理锁验收。

## 6. P2任务：仅在有余力或老师新增要求时开展

- 用维护中的库试做SPAKE2+独立对照：可信注册、验证记录、标准测试向量、服务端材料泄露边界；暂不替换主线。
- 把现有音频软件实验接真实USB音频：测设备、距离、噪声、误码、同步和重放，验证恢复包仍走密码学认证。无需新写一套开门协议。
- 测量后再决定requests.Session连接复用、握手合并及性能优化，不能用密码原语CPU速度推断端到端开门耗时。
- Android、直播、OTA、TPM/安全芯片均不作为当前关键路径。

## 演示前准备

1. 一次性手动开启 Docker 和所需隧道，确认当前安装完成迁移、HTTPS 证书受信。没有 Windows 自启任务或自动重连。
2. 打开正式 HTTPS 入口，用项目账户和本人身份验证器登录。刚消费的验证码不能再次用于开门或改密，等下一组代码。
3. 确认设备与摄像头真实在线；无执行器时显示 UNAVAILABLE/UNKNOWN。网页刷新旧照片与主动拍摄是不同操作。
4. 验证链路展示后，明确说明开门授权不等于门已打开；不能用模拟状态或演示快照充当实机证据。
5. 投屏隐藏密码、二维码、密钥、访客凭证和个人原始照片。截图图册的演示数据要保持标注。

## 8–10 分钟演示顺序

| 时间 | 展示内容 |
| --- | --- |
| 0–1 分钟 | 课题、现有硬件和范围 |
| 1–2 分钟 | 系统架构、服务端权限与信任边界 |
| 2–3 分钟 | MFA 登录、HttpOnly 会话、设备绑定 |
| 3–4 分钟 | 真实相机主动拍摄和私有媒体访问 |
| 4–6 分钟 | 人脸/PAD/TOTP、一次性授权、真实失败回执 |
| 6–7 分钟 | 访客额度、撤销、审计和报警 |
| 7–8 分钟 | 密码分发、音频软件实验、性能测量方法 |
| 8–10 分钟 | 回归证据、备份迁移、限制及后续硬件实测 |

密码存哈希，TOTP 秘钥可恢复地认证加密，设备消息认证加密，TLS 验证服务器身份：不要把不同安全目标混成一个“加密算法更强”的结论。

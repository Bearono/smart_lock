# 安全与功能复核 · 2026-10-18

## 结论与范围

本轮复核 Windows Docker、Vue 前端、Flask 后端、共享协议及 Pi 设备代码。软件回归、隔离浏览器业务、生产配置 HTTPS 会话和 amd64 设备镜像验收通过。结论对应当前工作区源码，不表示已经部署到原有安装，也不表示最新远程 CI、实体锁、真人防伪或声学实机验收完成。

main 按用户要求保留旧代码；本轮在 develop 工作区实施，没有改写 main 或历史。电脑没有安装自启、计划任务或自动重连，容器 restart=no。Docker 仅按授权一次性启动。2026-10-18 访问已配置树莓派地址时 SSH 超时，本轮未对 Pi 部署或实机结果作成功声明。

## 问题与修复

| 发现 | 修复与验证 |
| --- | --- |
| TOTP 秘钥明文落库 | 独立用途派生的 Fernet 认证加密；原始数据库、幂等迁移和错误密钥拒绝回归 |
| 同一时间步 OTP 可以跨挑战或接口重复使用 | 账户锁及数据库条件更新原子消费；登录、开门、改密、解绑共享状态；并发及跨接口回归 |
| 新密码继续依赖历史 bcrypt 配置 | 新密码 scrypt N=131072/r=8/p=1，随机盐；正确认证后事务内升级旧 bcrypt；按 worker 限制内存型运算并发，验证 512 MiB 容器中的并发登录 |
| 浏览器 JWT 存在 localStorage，退出仅清理本地 | HttpOnly/Secure/Strict Cookie、CSRF、服务端 jti 持久撤销；重载恢复、多 worker 与重启后撤销验证 |
| 私有快照在磁盘为明文 | AES-256-GCM，随机 nonce，AAD 绑定文件和设备；授权后解密；篡改、替换和迁移回归 |
| 历史协议和弱配置存在降级空间 | 生产拒绝 v2、旧上传及关闭 Cookie/CSRF 安全配置；非回环设备要求 HTTPS |
| SMTP TLS 未显式确保主机名验证 | SMTP_SSL 使用 ssl.create_default_context()；CERT_REQUIRED 与 check_hostname 断言 |
| 两层 Nginx 重复输出安全响应头 | 入口隐藏上游重复值，统一安全头和 CSP；独立 HTTPS 实际响应检查 |
| 已知漏洞依赖及过时包装层 | 升级 PyJWT、urllib3、Werkzeug、setuptools、wheel；直接使用 dlib 固定模型；漏洞及运行验证 |
| 两份 vendored SPAKE2 可能遮蔽固定依赖 | 移出运行路径，保留历史快照；结构检查阻止重新出现 |
| 虚拟环境、缓存和历史敏感数据进入源码索引 | 从当前索引移除，保留本机原件与历史；收紧 Git、容器和源码包边界 |

固定 IV、缺少认证的历史 ECC/CBC 示例已移到 examples/legacy_crypto，运行路径不再导入。生产 v3 使用 SPAKE2、HKDF-SHA256、双向确认和 AES-GCM；课程比较实验与生产路径隔离。控制参数、升级方法和依据见 [安全基线](../security.md)。

## 运维和剩余条件

1. 正式升级须停写、备份数据库和媒体、另存密钥，在原持久密钥下执行 init-db。升级密文不能交给旧代码；回滚须同步恢复旧数据及匹配代码/密钥，不能仅换镜像。
2. 主密钥用途派生不是 KMS/HSM。密钥和数据同时泄露时不再保密；未提供在线主密钥轮换。Pi 模板依赖文件权限和主机保护，没有 TPM/TEE 或模板磁盘加密。
3. 用户保留的旧 main/Git 历史仍包含历史敏感文件。当前索引清理不是历史清除；历史密钥和旧秘密不能重新使用。公开完整历史仓库前须单独处理。
4. Python SPAKE2 不是常数时间实现，本项目应用信封未通过第三方密码协议审计。使用标准原语不代表工业认证、ASVS 或 FIPS 认证。
5. 真人及照片/打印攻击、不同光照/角度测试需本人配合，记录次数、阈值、耗时、误拒和误受；当前不能宣称 FAR/FRR、活体等级或长期可靠性。
6. Pi 恢复连接后部署新版，复核拍摄、私有读取、认证及无执行器失败闭环。Android、实体锁按本轮范围排除；声学实机受硬件限制。

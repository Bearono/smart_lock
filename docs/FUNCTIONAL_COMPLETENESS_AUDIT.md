## 结论

**不能认定整套实物系统已经完全完成。** 已有软件核心链路和自动化证据，但物理锁执行、活体检测、Pi 实机性能与摄像头联调仍有缺口。网页可用、命令已提交、设备声称执行、锁舌真实到位是不同层面的结果。

本次核查同时检查前端入口、后端路由、设备进程、部署配置及已有测试。没有课程任务书，因此下表是现有实现和成品对标的核查，不代表老师规定的必做范围。

## 本轮发现并修正的问题

- 历史查询缺少当前设备筛选。本轮同时修改前后端，并增加未授权设备拒绝测试，避免切换家门后展示混杂记录。
- 离线设备仍可点击控制。本轮禁用离线控制并明确原因，测试同时确认在线且锁状态未知时仍允许主动上锁。此限制是 UI 行为，不能当作服务端防护。
- 小屏快照容器因最小高度与宽高比产生内部溢出。本轮明确宽度及最小宽度并重新检查，不只依赖父容器裁切。
- 视觉样式混在单个大文件。本轮按页面职责拆分，复用设计令牌和业务加载器。
- 升级容器后 HTTPS 代理缓存旧地址，出现 502。本轮给 Web、服务器 TLS 与设备 TLS 代理配置 Docker DNS 动态解析；服务器部署需通过重建上游而不重启代理的检查。实现依据：[Nginx proxy_pass](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_pass) 与 [resolver](https://nginx.org/en/docs/http/ngx_http_core_module.html#resolver)。

截图位于 `FE_smart_lock/smartlock/test-artifacts/`。这些截图只验证界面与测试链路。生产数据和测试数据分离。

Docker 已重新构建并部署；HTTP 与 HTTPS 就绪接口和 HTTPS 首页返回 200，HTTPS 使用本地 CA 完整校验。修复动态解析后，再次重建 backend 和 web 上游而不重启 TLS 代理，链路仍通过检查。新登录 WebP 资产由部署服务返回，内容大小与源码一致。部署后的浏览器验收加载实际构建资源，API 使用隔离拦截夹具；真实 API 联调另在一次性 Flask 数据库上运行，不能混称为生产数据验证。

## 实物闭环的下一步顺序与验收条件

1. 明确锁具电气参数、继电器接线、开锁/上锁动作以及反馈传感器，再实现 `Actuator`。断电、卡阻、重复命令与超时应返回可信结果；必须通过实物开闭测试才标记完成。
2. 在 Pi 上完成摄像头和人脸模板登记，用实际家庭光照样本测误识、拒识及延迟；模板登记的权限、替换与删除需要闭环。
3. 若课程要求人脸抵御照片/视频攻击，加入 PAD 与服务端策略并做攻击样本验收；不得把相似度阈值当作活体检测。
4. 在 2GB 实机上记录推理峰值内存、CPU、温度和连续运行情况，并验证重启后队列、授权与重放防护状态。
5. 按任务书决定直播、门磁、恢复流程和网页登记是否必做；如需达到日常家庭产品标准，则这些仍属于待交付范围。

在以上条件完成之前，项目应描述为“具备核心软件链路、尚待实物闭环验收的智能门锁与摄像头系统”。

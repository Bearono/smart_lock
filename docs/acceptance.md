# 验证与支持范围

## 支持的运行组合

| 组件       | 验证环境                                          |
| ---------- | ------------------------------------------------- |
| API 与 Web | Docker Linux 容器，HTTPS 入口，SQLite 持久卷      |
| Android    | API 26 起构建支持；iQOO 真机完成联调              |
| 设备服务   | ARM64 树莓派、CSI 摄像头、原生 Picamera2          |
| 执行服务   | 独立 ARM64 模拟门锁，含 x86 主机上的 ARM 仿真运行 |

## 自动化检查

| 检查层         | 覆盖内容                                             | 入口                           |
| -------------- | ---------------------------------------------------- | ------------------------------ |
| 仓库           | 组件路径、依赖边界、文档链接、敏感产物隔离           | `python manage.py check`       |
| API 与共享协议 | 认证、权限、并发、重放、授权消费、私有媒体与数据迁移 | `python manage.py verify`      |
| Web            | 状态流转、静态检查、构建、响应式布局和文字放大       | Web 单测与浏览器测试           |
| 交互材质       | 按压回弹、动态折射、减少运动、对比度与资源释放       | `npm run test:material`        |
| Android        | 来源策略、JVM 回归、APK 对齐与签名                   | `test_jvm.py` / `build_sdk.py` |
| 设备镜像       | amd64/arm64 架构、导入和模型/相机边界                | CI `device-image`              |
| 模拟门锁       | 签名、过期、去重、故障和重启持久化                   | CI `lock-simulator`            |

测试采用隔离数据库和确定性夹具。每次发布以对应提交的 [CI](https://github.com/Bearono/smart_lock/actions/workflows/verify.yml) 和构建摘要为依据，检查报告保存在 `releases`，不进入运行时源码。

## 实机验证基线

2026-11-16 已完成网页和 Android 的真实 CSI 拍照、人脸与活体检查、TOTP、一次性授权、模拟开锁、回执和重新上锁闭环；应用切换身份验证器和连接设置往返正常。

后续工程整理版本 `e54fd0e` 已通过 [8 项 CI](https://github.com/Bearono/smart_lock/actions/runs/43739401805)，完成树莓派更新和 30 项设备回归，Android 安装文件与构建摘要一致。软件检查与实机结果分别记录；个人照片和模板保留在部署环境。

## 运行边界

- 演示要求电脑服务、树莓派服务和 SSH 转发在线；USB 客户端还需要 ADB 端口转发。启动和恢复步骤见[部署指南](../deploy/README.md)。
- 执行端采用模拟锁，接口与界面明确返回 `SIMULATED`；当前范围不包含实体锁和继电器驱动。
- 不包含音频认证、整机启动编排、断线自动重连和长时间稳定性验收。
- 三次手机照片展示样本已被拒绝；尚无覆盖不同人员、光照和攻击类型的 FAR/FRR 或活体性能统计。
- SQLite 已验证；MySQL 迁移、邮件外部实际送达和现场安全认证尚未纳入验证。

协议、密钥和端点信任限制见[安全基线](security.md)。

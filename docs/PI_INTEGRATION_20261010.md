# Pi 4B / OV5647 接入记录（2026-10-10）

## 实物与已验收边界

本轮实际连接 Pi 4 Model B / 2GB、Camera Rev 1.3（系统识别 OV5647）。没有锁具、继电器、门磁等硬件，因此所有锁状态保持 UNKNOWN，默认执行器不会假装执行成功。尚未进行真实身份登记和照片攻击实验，不能宣称人脸 MFA、活体或实物开锁已验收。

## 软件调整

- 增加原生 CSI 部署 profile，以系统 Picamera2 使用当前 Raspberry Pi OS 的 libcamera；USB/Docker profile 保留，不把单个视频节点挂载当成 CSI 兼容性证明。
- CameraManager 从 SMART_LOCK_CAMERA_BACKEND 选择采集方式，明确 picamera2 时不退回其他设备。修正 RGB888 数组的 BGR 通道契约，避免原来的额外红蓝交换。
- 采集异常清理相机资源，下次可重新初始化；worker 退出释放相机；模型推理和采集分别由既有锁串行化。
- 原生依赖在普通用户虚拟环境中安装，相机相关系统包由 APT 管理。Python 3.13 profile 使用 dlib 20.0.1，单任务构建；固定 Python 应用依赖，记录实际系统视觉库版本。
- 原生 systemd 用户服务：单进程、双线程、内存和进程数限制、仅 loopback HTTPS、独立设备口令和服务证书。开机驻留与管理员创建已向用户单独请求并获得授权。
- 双向 SSH 联调隧道不公开局域网端口，保持 SSH 主机密钥及两端 HTTPS 校验。关闭电脑或隧道会中断联调通信；该拓扑不是长期生产部署方案。

## 已获得证据

设备为 aarch64、Debian 13（Pi OS），有效内存约 1.8GiB，29GB 根分区。基础相机工具识别 2592×1944 OV5647，并实际拍照成功。

修改后的 CameraManager 实机取到 5 帧 640×480 BGR，采集耗时分别为 1531.2、28.7、66.7、67.0、65.9ms；该进程峰值 RSS 168816KiB，退出后相机对象已释放。这仅是短时采集数据，不是人脸推理性能或长期可靠性指标。采集照片保留在本机忽略目录，不上传 Git。

稳定源码验收：后端 108 项、前端 12 项和 lint/typecheck/format/build 全部通过；AMD64 设备测试 17 项通过，新增颜色、资源恢复和明确 CSI 选择边界测试。原始证据在 releases/verification-pi-20261010。ARM64 系统环境中的新增相机测试 4 项通过；不能拿 AMD64 结果代替完整 ARM64 设备验收。

固定模型已在 Pi 校验；独立设备登记 ID 为 pi_csi_01，尚无真实人脸模板，识别配置就绪必须返回 503。用户树莓派登录密码不写入源码、配置或报告；设备随机口令、TLS 私钥和 SSH 私钥分别保存在忽略目录/本机 SSH 目录，不打包。

SPAKE2 两端握手中位数 13584.8 μs、p95 16844.6 μs。该握手测量没有网络往返、TLS、数据库和 v3 确认往返；不能把它称为完整远程认证时延。

算法 API 行包含实例构造和随机 nonce 分配，不是纯加密核心吞吐。完整信封行还包括 HKDF、规范 JSON、Base64、头部与随机请求 ID；输入先经过 Base64 组成业务对象，因此信封实际处理的数据大小大于原始输入。v3 使用其线程安全 nonce 计数器，而 v2 采用随机 nonce/IV。应分别比较两种算法调用或两种完整信封，不能把两层数据混作加密速度排名。

本次完整 v3 信封耗时低于 v2，仅说明这次主机测量。它不能证明 Pi 表现、网络吞吐、摄像头帧率、并发容量或安全强度；也不能证明 AES-GCM 在所有设备上优于 ChaCha20-Poly1305。v3 的选型依据还包括 AEAD 认证语义、上下文绑定和 nonce 生命周期，而非单一速度数字。

复现：安装共享协议与后端依赖后，在仓库根目录运行 `python deploy/protocol_benchmark.py --iterations 100 --output releases/protocol-benchmark.json`。真实 Pi 测量应同时记录板型、系统、依赖、温度、CPU/内存、样本规模与后台负载，并重复测量。当前原始 JSON 位于本机 `releases/protocol-benchmark.json`，发布包收录副本 `verification/protocol-benchmark.json`。

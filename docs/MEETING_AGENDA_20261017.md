## 20–30 分钟：确定本学期主线与停止扩张的范围

建议共同目标：**完成一套能展示设备独立身份、密钥协商/轮换/退役、真实摄像头认证和可信执行结果的课程原型。**

建议必做：

1. 偏蓝定位与采集/登记流程统一。
2. 设备身份和密钥生命周期：已有轮换继续完善，补设备停用/退役、版本与审计。

4. 新环境复现、脱敏交付、统一状态表及可讲清楚的答辩。

建议预算允许时增加：实体锁 + 反馈 + 门磁的小门板演示；先询价，先核对驱动与脉冲要求。

## 老师可能追问的五个问题

1. **SPAKE2、KDC、RSA 密钥传输有什么不同？** 分别是基于共享秘密的认证协商、可信中心分发、面向接收方的密钥封装；当前只有 SPAKE2/v3 是设备主链路，后两者是对照实验。
2. **第一次共享秘密从哪里来？** 维护者生成并独立安全注入，不通过普通网页登录表单公开发放；PAKE 不消除首次登记问题。
3. **设备秘密泄露怎么处理？** 轮换/停用，撤销旧会话和派生能力并保留审计；版本与退役闭环是后续重点。
4. **有 HTTPS 为什么还做 v3？** HTTPS 保护传输，v3 展示独立设备身份、会话确认与消息生命周期；不能因此宣称后端看不到图像。
5. **怎么证明门开了、人脸可靠？** 真实锁反馈与独立人脸/PAD 实验；没有硬件或样本时明确边界，不拿 HTTP 成功、相似度或单次认证替代证明。

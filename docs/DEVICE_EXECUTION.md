# 设备命令运行契约

设备服务在 Gunicorn worker 初始化后分别启动命令轮询和摄像头心跳。默认命令间隔 1 秒，心跳间隔 30 秒；网络调用耗时计入实际周期。部署维持一个 worker，每个设备编号只运行一个服务实例，所有实例必须使用各自设备的持久化状态目录。

## 驱动边界

`paspberry_pi/command_executor.py` 的 `Actuator` 约定两个方法：`set_state(target)` 执行动作，`read_state()` 返回实测的 `LOCKED`、`UNLOCKED` 或 `UNKNOWN`。驱动必须限制 I/O 时间，支持心跳与执行线程同时读取，并在自身内部协调读写。动作返回不代表成功，只有随后读取与目标一致且未过期，才生成 executed 回执。

当前启动配置使用 `UnavailableActuator`：读取为 UNKNOWN，动作明确失败。没有配置实物驱动时，网页命令会显示失败，不会假报已开锁。未来驱动在 `gunicorn.conf.py` 的初始化位置接入；当前软件验收只注入合成测试驱动，不访问 GPIO。

## 执行记录与故障恢复

- 同步回复先由传输层校验签名及请求绑定，再交给执行器。只接受合法命令 ID、目标状态和有限数值到期时间；拒绝过期或超过时钟偏差范围的命令。
- `DEVICE_STATE_DIR/executions.db` 在动作前提交唯一命令记录。同一 ID 不再执行，载荷改变则拒绝；多个执行器竞争相同 ID 时只有一个能预约成功。
- 正常结果先落盘再发回执。网络故障仅重试回执，不重做动作；后端 404/409 作为不可继续提交的终态处理。
- 若进程在动作期间退出，重启保留 executing 预约，不重做、不推断成功；到期后记录 failed/UNKNOWN。后端可能已显示 expired，因此用户应以未知实际状态处理，不能依赖猜测的开关状态。
- 每个轮询周期最多发送一条回执，优先最新命令，避免历史回执挤占当前命令处理。后端同步失败仍尝试发送已有回执；请求超时遵循传输层 10 秒限制。
- 命令到期一天后清理执行记录及未送达回执。过期命令仍会在入库前被拒绝。不要在命令有效期间删除或更换状态卷；主机时钟必须保持准确。

软件提供的是保守的至多一次执行策略。进程在“记录已提交、动作未开始”之间崩溃会放弃该动作；这是避免重启重复开锁的明确取舍。权限撤销和物理执行跨网络，不能承诺撤销能中止已经在设备开始的动作。

## 自动化覆盖

执行器回归覆盖持久化顺序、重复与并发命令、载荷冲突、驱动异常/反馈不一致、过期边界、进程中断、回执丢失、终态拒绝、日志保留及线程退出。回环 HTTP 验收通过真实后端签名同步，把命令交给同一执行器，再以加密回执查询最终结果；没有使用真实锁体。

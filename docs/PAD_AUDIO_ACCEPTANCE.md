# 人脸防伪与音频软件交付

2026-10-11。当前排除实体锁与 Android；音频纳入软件范围。现有实物只有 Raspberry Pi 4B/2GB 和 OV5647。没有麦克风、声卡、扬声器与门锁反馈，不能把软件回环当作声学实机或物理开门验收。用户选择稍后进行真人与照片攻击测试。

## 人脸认证

采用 [Minivision Silent-Face-Anti-Spoofing](https://github.com/minivision-ai/Silent-Face-Anti-Spoofing) 的 MiniFASNetV2（Apache-2.0），固定上游提交 `b6d5f04ad78778917853b25c778acef6d5626d15`。`deploy/export_pad.py` 校验来源、权重与许可证；安全加载权重后导出 ONNX。五组输入的 PyTorch/OpenCV 推理结果差异低于 0.001；这仅证明转换一致性。

Pi 使用 OpenCV DNN，无需在设备安装 PyTorch。ONNX SHA-256 固定为 `b5156dece1bdc64a6806d037a783a2e3db178fb054aa71c6518992de68d5b841`。模型缺失或改变时生产就绪失败，认证拒绝。输入为同一摄像帧上的单张脸，按上游 2.7 倍裁剪、80×80 BGR、原始 0–255 浮点值处理，取 live 类分数。

生产服务端同时要求身份相似度 ≥0.90、防伪分数 ≥0.80、匹配设备及会话 nonce；后续仍按策略要求 TOTP。防伪分数缺失或低分不能验证人脸；异常类型、非有限数和越界值拒绝。日志保存原始防伪分数与失败原因，历史记录可空。新增列采用可重复执行的兼容迁移。

0.80 是初始策略点，未经当前摄像头的误拒率/攻击接受率校准，不代表经过认证的活体安全水平。单个被动模型不能保证抵御重放视频、面具或新型攻击。它也不构成摄像头可信执行环境证明。

后续实测：本人多距离/光照/角度，每种至少五次；手机显示照片与打印照片各至少五次，录像攻击另记；记录真实/攻击分数、通过情况与耗时。另一个人需本人同意。当前没有这些独立试次，不能填写商业准确率或宣称照片攻击已验收。

## 音频软件链路

集中在 `smartlock_protocol.audio`，通过包的 `audio` 可选依赖安装固定 NumPy。48 kHz、FFT 256、循环前缀 64、64 个 BPSK 子载波；载波约 3–14.8 kHz，两个训练符号用于同步和短多径均衡。载荷限制 1–2048 字节，录音最长十秒，使用单声道 16 位 PCM WAV。CRC 只检测损坏，不认证身份。

`envelope_wav` / `envelope_from_wav` 承载 v3 密文信封。恢复结果仍不可信，必须交给正常后端认证与数据库重放检查；不能直接根据音频内容执行开门。测试覆盖真实 v3 会话、篡改和接收端重启后的重放拒绝。

`deploy/audio_lab.py` 验证 KDC 加密票据与 ECDSA 签名的 RSA-OAEP 密钥包经过 OFDM、PCM 和模拟延迟/噪声/极性变化后分发成功，并拒绝票据重放。密钥只存在进程内存，不写入报告；该课题对照不提供生产 KDC 注册或持久化票据生命周期。Windows 与 ARM 均可运行。不会打开声卡或自动播放声音。

运行示例（已安装共享包与 audio 依赖的 Python 环境）：

```text
python deploy/audio_lab.py --output releases/audio-lab.json
```

本次 Windows/ARM 的公钥包均为 582 字节，对应 0.507 秒波形。软件总用时分别约 0.060/0.448 秒，包含随机密钥生成；不能比较为实际网络或声学时延。算法没有采样率漂移补偿或纠错编码，模拟成功不保证房间声学传输稳定。

声学物理指纹需要真实发声与录音、重复采样和跨设备负样本；位置及房间响应也会影响特征。缺少这些硬件与数据时，不能生成虚假的设备指纹或把模拟通道作为可信身份。

## 本轮软件证据

后端 134 项、前端 13 项自动测试通过；lint、类型、格式和构建通过。Edge 浏览器验收包含人脸防伪分数详情、35 项响应式与 5 项文字放大检查。业务测试使用隔离夹具，不代表真实人的认证结果。Pi 上防伪预处理、模型校验与推理的 20 次合成像素测量中位数 19.472 ms、p95 20.437 ms；Windows 对应中位数 4.655 ms、p95 5.451 ms，不包括真实检测与身份匹配。Pi 的两项 PAD 预处理/完整性测试通过。

部署前本次会话的 30 分钟联机观察完成：31 次采样全部就绪 200、设备在线、摄像头 ONLINE，缺少执行器时保持 UNAVAILABLE/UNKNOWN。观察期间更新了 Pi 模块，后端升级在观察结束后进行；该记录不是最终后端版本连续运行 30 分钟的证明。
